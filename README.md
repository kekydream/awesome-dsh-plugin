# dsh-meeting-room · 会议记录

DeepSeek Harness 的会议插件：**本机转写、发言人分离、要点与工作安排、手写笔记、复盘与纪要**。

音频不出本机；转写用随 DSH 安装的 SenseVoice，手写识别用随插件安装的本地小模型。**不登录也能**写字、识别、建任务、出纪要。

设计文档：
- [DESIGN.md](DESIGN.md)——「会话 ↔ 会议」与「登录用户 ↔ 会话」的完整关系设计；
- [FEATURES.md](FEATURES.md)——会议类型（晨会/复盘会/例会/总结会）、跨会提炼与月度评分的增量功能设计（设计稿，尚未实现）。

## 安装

```sh
dsh plugin --profile <你的profile名> add dsh-meeting-room
```

装完确认这一层已经生效：

```sh
dsh --profile <你的profile名> --dump-config   # 应出现一层 "# == dsh-meeting-room"
```

**安装后需要重启 Harness**：宿主半边每个进程只加载一次。

## 前提

| 依赖 | 说明 |
| --- | --- |
| **SenseVoice 语音识别** | 由 DSH 安装包提供（`sherpa-onnx-node` 声明为 peer 依赖，随安装解析）。若你的 DSH 未包含 speech 相关包，转写不可用，其余功能不受影响 |
| **`onnxruntime-node`** | 随本插件安装，用于手写识别。若安装时 pnpm 提示忽略其构建脚本，Windows x64 上属正常现象，模块仍可加载；其他平台如加载失败，请在该 profile 里 `pnpm approve-builds` 后重装 |
| **`pinyin-pro`** | 随本插件安装，用于会议术语的同音订正 |
| **Python + python-docx** | 仅「导出 Word」需要。优先使用 DSH 运行时自带的 Python；若不含 `python-docx`，在其中 `pip install python-docx`。没有 Python 时其余功能不受影响 |

**模型在首次使用时联网下载**（不在包内），下载后校验大小与 sha256：

- 语音转写模型（SenseVoice）：由 DSH 的「语音输入」功能提供；
- 发言人模型（约 28 MB）：3D-Speaker CAM++；
- 手写识别模型（约 77 MB）：ModelScope DAMO 手写行识别。

**自动下载**：插件会主动检查这些模型是否就绪。语音模型未就绪时：

- 打开会议面板即显示提示，面板内可直接点击「开始下载模型」，进度实时显示；
- 点「开始记录」会弹出对话框，提示先下载模型（此时录制无意义）；
- 若「语音输入」功能尚未启用，点击「立即下载模型」会**自动启用语音输入功能并下载模型**，全程无需离开面板；
- 下载中关闭面板再打开，会自动续读进度直到就绪。

下载源为 ModelScope 与 GitHub 代理；若全部不可达，对应功能会明确报错，其余功能不受影响。

> **麦克风权限**：录制需要系统允许 DeepSeek Harness 访问麦克风。若点击「开始记录」后未进入录制状态，请到系统「设置 → 隐私 → 麦克风」确认已授权，并确认没有其它应用占用麦克风。

## 功能

### 会话与会议

- **一会话、一会议（1:1）**：新建会话的那一刻就建好它的会议记录；录音、要点、任务、
  笔记、文档全部写进同一份，换会话即换会议，彼此独立；
- 子代理 / 团队成员等代理会话不单独建会议，它们的一切活动记到所属根对话的会议里；
- 会话被分支（fork）时，新分支拿到自己的一份新会议；
- 会话销毁时：空会议直接回收，不留空文件；有内容的会议保留为历史记录，可在
  「会议管理」里回放或一键打开原会话；
- 录音中的会话不能被静默归档；强制归档会在停止录音（文件补全后保存）之后进行；
- 会议记录是**本机产物**：归本机会话所有，与登录账号无关，换账号登录不影响任何记录。

### 录制与转写

- 麦克风采集 → 停顿切分（0.5 秒静音、最长 5 秒一段）→ 本机 SenseVoice 转写；
- **发言人识别默认开启**：每条讲话标注说话人；会议结束时对整场重聚类，同一声音统一编号；
- **发言人命名**：把 S1/S2 换成真实姓名；姓名在所有输出（实录、SRT、Markdown、纪要、给模型读的文本）生效，且会终重聚类后跟着声音走。

### 手写笔记

- 手写板、系统手写、会议术语三个页签，由面板上的「笔记」按钮统一开合；
- **本地手写识别**：离线、约 43 毫秒一行、多行自动分行；
- **圈选 / 轻点选字 / 长按开始圈选**；选中后可「识别选中」或直接「转为任务」；
- 识别结果**按行**各给一个「转为任务」，多行笔记可逐条建任务。

### 要点、工作安排与纪要

- 从实录用规则抽取草稿要点（决议 / 要点 / 风险 / 待确认）与草稿工作安排；
- 两者都可**修改**（内容、类型、负责人、时间、优先级），也能确认或删除；
- 负责人可从人员名册与已命名发言人里**搜索选择**；时间用**日期时间选择器**；
- **任务草稿必须由人确认**才成为已确认，且**只有已确认任务会被推送**；
- 「生成纪要」本地成文（Markdown）；「导出 Word」生成 `.docx`。

### 复盘

- 选择你的角色：**主持人 / 参会人 / 旁听**；
- 「复盘会议」把整场实录发进当前对话，按角色给出关注点，要求模型只依据实录、标注不确定处，产出可存档文档；
- 复盘文档通过工具写进会议记录，在面板「会议文档」里可直接查看。

### 术语与纠错

会议术语每行一条，三种写法：

| 写法 | 作用 |
| --- | --- |
| `错词=正确词` | 字面替换 |
| `陈一鸣` | **同音订正**：听到「沉一明」也会改成它 |
| `*李` | 连**单字**也按同音订正（单字容易误替换，只在对某个姓氏有把握时用） |

**原始转写永远保留**：订正只写入 `revised`，界面、SRT、Markdown、纪要一律「订正优先、原文兜底」，鼠标停在句子上可看原文。

会议结束后还可「二次纠错」：请 Agent 读整场实录，按上下文统一人名、术语与明显错字，并留下**订正对照**。

### 推送到钉钉 / 企业微信

在左侧「会议管理」页配置：

- **机器人设置** tab：群机器人 webhook、推送方式（群机器人 / 工作通知 / 两者都发）、钉钉企业内部应用（AppKey / AppSecret / AgentId）；
- **人员管理** tab：名册（姓名 / 手机号 / 钉钉 UserId），可手工维护，也可**从钉钉同步**——先「读取部门」，再选**某个科室**或**全部组织**导入。

推送时按**负责人分组**、每人一条消息：群机器人用手机号 @人，工作通知私发给该负责人的 UserId。

> 通讯录同步与工作通知都需要企业内部应用具备相应权限；`user/list` 返回手机号还需字段权限，没有该权限时只同步到姓名与 UserId。

## 数据位置

| 位置 | 内容 |
| --- | --- |
| `$DSH_HOME/meetings/` | 录音 WAV、导出的 SRT / Markdown / Word、手写笔记 PNG |
| `$DSH_HOME/meeting-room/meetings/` | 会议结构化记录（要点、任务、笔记、订正、发言人姓名），重启后自动恢复 |
| `$DSH_HOME/meeting-room/webhooks.json` | 机器人地址、企业内部应用凭据、人员名册 |
| `$DSH_HOME/speech-to-text/speakers/` | 发言人模型 |
| `$DSH_HOME/handwriting/` | 手写识别模型 |

## 已知限制

- **转写是请求/响应式的，不是流式**：文字在说话人停顿后成段出现（最长 5 秒一段），没有逐字上屏；
- 一条 cue 若跨说话人，只记主要的那一位；
- 手写识别是**整行**模型：请横向书写、字距不要太挤，连笔过多会影响准确率；
- 系统手写面板依赖 Windows 自带手写功能，在 Electron 里可能唤不出，此时可直接用输入框；
- 录音只写 WAV；会议结构化记录不自动清理，需自行管理磁盘。

## 目录结构

| 路径 | 作用 |
| --- | --- |
| `index.js` | 宿主半边：事件接线（会话↔会议生命周期、归档准入）、路由注册、工具注册（`meeting_read` / `meeting_write` / `meeting_note_write` / `meeting_revise` / `meeting_save_document`）；业务逻辑在 `host-*.js` |
| `client.js` | 浏览器半边：采集、会话右侧面板、会议管理页 |

| `handwriting-worker.js` | 子进程：本地手写识别 |
| `minutes-docx.py` | 用 python-docx 把纪要渲染成 Word |
| `cordis.patch.yml` | 组合包 patch，把宿主行插进 profile 层栈 |
| `tools/recognize-note.mjs` | 开发工具：对一张手写 PNG 直接跑识别 |
